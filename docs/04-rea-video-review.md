# 04 · rea-video 评估与改进方案

> [JuneYaooo/rea-video](https://github.com/JuneYaooo/rea-video)（Apache-2.0，约 3000 星）：逐镜头逆向拆解视频的制作方式，并给出复刻方案。本文记录对它的阅读结论、在我们三类视频上的实测，以及在它的基础上可以做得更好的地方。

## 1. 它做对了什么（值得直接沿用）

1. **分析的目标是"怎么做出来的、怎么复刻"**，不是风格统计。每个镜头先判制作方式（10 类），再给复刻路线。我们之前的参考分析偏成了统计区间和审美评论，这一点要纠正。
2. **逐镜中间表示 `breakdown.json`**：特征、证据、概率、叠加层、复刻方案；规则修改后可以直接用缓存特征重新分类，不必重新解码。
3. **证据与置信度的纪律**：
   - 确定性工具负责能测量的问题，看图（VLM 或 agent）负责需要理解的问题；
   - 有融合规则和硬约束；工具与 VLM 冲突时标记"有分歧"，必须复核；
   - 确定不了就写"待确认"。
4. **agent 看图复核协议**：`review_tasks.json`（按优先级排序，只给工具结果、不给 VLM 答案）→ `review_answers.json` → `apply-review` 融合，不直接覆盖。
5. **代码渲染镜头的逐镜动效时间轴**：元素出现 / 消失的时间、位置、方式（滑入 / 描线 / 放大）、缓动类别、颜色、文字、截图，以及按画面特征归纳的 Remotion 实现方式。
6. **剪辑包装层单独一条时间轴**：字幕、花字、标题、标签、贴纸，样式靠测量，可导出 SRT / ASS；音效对齐到画面事件。
7. **声音拆成三条轨**：人声 / 配乐分离、BPM、调性、段落，切点卡节拍与随机比较。
8. **评测**：真值来自生产记录，分调参集和留出集，按时长加权，`RESULTS.md` 留痕。
9. **记忆**：用户的纠正会被记下并反馈到复核任务，积累后可导出成评测样本。

## 2. 实测（未开 VLM，不做 agent 复核，即确定性层的基线）

运行环境：独立 venv，`rea-video decompose <video> --lang zh`。人声分离模型首次运行时自动下载成功。

| 视频 | 真值 / 目测 | rea-video 结果 | 判断 |
|---|---|---|---|
| **battery-80**（我们的演示片，19s，竖屏，固定窗口版式，纯代码渲染） | 8 镜、7 个切点；渲染器为 Remotion | **只切出 3 镜（召回 2/7）**；最后一"镜"长 15.7s，包含 5 个真实镜头；制作方式：代码 91% + 3D 9%（第 2 镜为生成图片加推拉，判成 3D）；**识别出渲染器 Remotion** ✅；动效事件只测到 7 个，真值约 40 个（3 种积木的每次入场、描线、弹出、脉冲） | 切点在固定版式下严重漏检；动效时间轴召回约 15% |
| **Kurzgesagt 前 2 分钟**（横屏 60fps，扁平矢量 2D 动画） | 我方检测 10 个切点，看图确认另有 1 个（59.5s） | 17 个切点：10 个与我方一致，59.5s 判对（我方漏了），**另有 6 个误报**（42.3s 聚光灯亮起；109–114s 同一镜头内辉光增强被切成 5 段）；**制作方式全错**：静图推拉 39% + 3D 29% + 代码 27% + AI 5%，真值是 2D 动画 100%；把画面标签当成"字幕 8 句"（原片没有字幕） | 切点精度约 0.65；2D 动画完全测不出（文档也承认这一类需要看图） |
| **差评君·静电**（竖屏，窗口版式内放实拍素材和黑底 MG 图解） | 素材实拍约一半，MG 图解约四成 | **3D 渲染 98%** + 代码 2%；33s 的黑底 MG 讲解段被当成一个镜头；字幕 191 句 | 版式模板的平涂色块主导了纹理统计，窗口里的实拍素材被判成 3D |

另有两个共性问题：

- **实拍维度对渲染画面产生噪声**：打光、机位、景别是为实拍设计的，对代码 / 动画画面也照常输出，比如给演示片写出"夜景弱光、背景浅景深"。报告虽然注明"不是拍摄方案"，但占了大量篇幅，没有信息量。
- **动效时间轴每镜最多 20 个事件**，而且持续运动（流动粒子、漂移）会被并入"持续运动层"。长镜头里的 MG 讲解因此几乎测不到内容。

## 3. 可以做得更好的地方

按对我们目标（MG + 3D + 剪辑，代码生成视频）的价值排序。每一条都有上面的实测作为证据。

### 3.1 版式感知的切镜与分类（修复实测中最大的错误）

- **问题**：固定版式（窗口、画中画、边框、常驻标题栏）在中文短视频里很常见，我们自己的引擎也在用。rea-video 用整帧变化面积判断切镜、用整帧纹理判断制作方式，被不变的模板区域稀释和主导。
- **做法**：先检测全片几乎不变的模板区域（我们 `measure/layout.py` 已经实现：逐像素时间方差 → 最大变化连通域），**切镜、纹理、动效都只在内容区内计算**，模板本身单独记为"版式模板"叠加层。
- **验证**：在 battery-80 上，我们的"版式检测 + 硬切 + 视觉节拍"两级检测把 7 个真实切点全部找到（2 个作为硬切、5 个作为节拍，时间偏差 ≤ 0.31s），没有误报；rea-video 只找到 2 个。注意：只靠硬切检测，我们自己也只找到 2 个，因为黑底图解之间的切换在像素上更像节拍。所以 3.1 必须和 3.2 一起做。

### 3.2 两级时间结构：镜头 → 视觉节拍

- **问题**：MG 讲解常在同一背景上连续换内容。rea-video 把 15–33 秒的连续 MG 段当作一个镜头，动效事件又有上限，内容基本丢失。
- **做法**：在镜头内部加一层"视觉节拍"（构图的实质变化，我们在第一阶段已实现并做过人工复核）。动效时间轴、复刻单元、看图任务都以"节拍"为单位。镜头仍按硬切定义，用于剪辑统计。

### 3.3 能测出 2D 动画，以及区分代码动效和手绘或插画动画

- **问题**：2D 动画被列为"工具测不出"，评测集里一条样本都没有。Kurzgesagt 这一类全被判错，而这正是高播放量 MG 科普的主流形态。
- **做法**（确定性特征）：
  - 平涂色块加柔和渐变 / 辉光的"插画纹理"；
  - **非刚体的局部形变**（角色、器官在动，而不是整块平移 / 缩放）；
  - 分层视差（前后景以不同速度移动）；
  - 有限帧动画的节奏（按两帧 / 三帧一换）。

  路由也要细分：矢量插画动画 → SVG / Lottie / Rive + Remotion；代码动效 → Remotion 积木。
- **评测**：补充 2D 动画样本，可从我们的引擎合成，也可用授权的公开片段。

### 3.4 语音转写：时间轴锚定到旁白

- **问题**：rea-video 没有做语音转写，口播文案依赖 VLM 听写。字幕是否真是字幕、画面在旁白的什么位置切换，都无法测量。
- **做法**：接入 whisper 逐词时间戳（我们已实现，后端可插拔）：
  - **字幕判定**：OCR 文字与同一时刻的语音内容一致，才算字幕；否则算标签或画面文字。可以修掉 Kurzgesagt 的"字幕 8 句"和差评君的"字幕 191 句"。
  - **剪辑与旁白的关系**：画面切换落在旁白停顿处的比例、对齐短语边界的倍数（都与随机时刻比较）。Kurzgesagt 有 44% 落在停顿处，差评君约 1%，这是两种截然不同的剪辑方法，rea-video 目前测不到。
  - **旁白 → 画面映射**：每句话对应哪个节拍、画了什么，这是复刻讲解类视频的骨架。

### 3.5 按制作方式开启分析维度，渲染画面换成动效设计维度

- **问题**：打光、机位、景别对渲染画面没有意义。
- **做法**：沿用它的维度插件机制（`aspects` 的 measure / fields / summarize / check），按制作方式开关：
  - 实拍：保留现有维度；
  - 代码 / 2D / 3D：新增**设计体系**（每个场景的调色板角色：底色 / 主体 / 强调 / 语义色，跨镜头的复用）、**动效语言**（入场方式分布、间隔节奏、缓动、持续层）、**虚拟相机**（推拉摇移、尺度穿越、视差）、**母题**（反复出现的物体和角色）。

### 3.6 动效时间轴升级为"可执行"的元素轨迹

- **问题**：现在给的是"某区域在某时刻出现、向右移入、缓入缓出"这类文字描述；没有跨时间的元素身份、真实位移和缓动参数，没有弹簧检测，事件也有数量上限。
- **做法**：
  - 事件之后对每个元素做模板跟踪，得到位置 / 缩放 / 透明度随时间的曲线，拟合 cubic-bezier 或弹簧参数（我们 `track.py` 有雏形，改成对所有元素生效）；
  - 输出结构化的 `elements[]`：`{id, box, t_in, t_out, enter: {kind, from, dur, easing}, colour, text, crop}`；
  - **直接映射到我们的积木参数**：节点 / 标签 / 大字 / 图表 / 素材窗口，生成可渲染的 `storyboard.json` 草稿，不再停在文字建议。

### 3.7 闭环：复刻后再拆一遍，按元素比对

- **问题**：rea-video 对 AI 复刻会输出并排对比视频，但没有可量化的差异；代码镜头更是只有建议。
- **做法**：用同一套拆解跑我们的成片，与参考的 IR 逐镜、逐节拍、逐元素对齐比对：切点偏差、节拍时长、元素入场时间 / 位置 / 方式、调色板 ΔE、文字样式。输出评分卡，落到 docs/02 的 M 系列指标。

### 3.8 用自己的引擎合成带真值的评测集

- **问题**：rea-video 的评测集只有 41 条，没有 2D 动画，也**从未评测动效时间轴本身准不准**。
- **做法**：我们的渲染天然带完整真值（每个切点、节拍、元素的入场时间、方向、缓动都在分镜里）。可以随机生成大量分镜（不同版式、积木、转场、节奏）批量渲染，**自动得到切点 / 节拍 / 元素事件 / 制作方式的真值**，同时用作回归测试。真实视频的人工标注仍作为留出集。

### 3.9 跨视频的创作者风格

rea-video 一次只看一条视频。我们的 `profile_build` 能把同一作者的多条视频聚合成风格分布（版式、节奏、色彩、动效），还可以加上"设计体系"的跨片共性。这部分作为它之上的一层。

## 4. 落地方式

- **以 rea-video 为分析底座**（依赖，不 fork 改核心），我们做一个扩展层：
  ```
  rea-video decompose ──▶ breakdown.json
         │
  vh-analyze（我们的扩展）
    ├─ 版式检测 → 内容区内重新切镜（3.1）
    ├─ 视觉节拍（3.2）
    ├─ 2D 动画特征（3.3）
    ├─ 语音转写锚定（3.4）
    ├─ 动效设计维度（3.5，以 aspects 插件形式注册）
    └─ 元素轨迹 → storyboard 草稿（3.6）
         │
  breakdown+.json ──▶ 我们的引擎渲染 ──▶ 再拆 ──▶ 比对评分（3.7）
  ```
- 通用性强的修复（3.1 版式感知、3.4 字幕判定）**可以作为 PR 回馈上游**，附上实测样本和评测结果。
- 我们 `measure/` 中与它重叠的部分（切点、OCR、音频）逐步退役；保留它没有的：版式、节拍、语音对齐、跨片聚合、随机基线。
- 评测先做 3.8：没有可靠的真值，后面每一项改进都无法证明有效。
