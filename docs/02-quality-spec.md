# 02 · 质量规范

> 目标：把"高质量"拆成可校验的条目，并让 agent 稳定达到。规范中的数值**来自参考视频的分布**（见 [01](01-reference-analysis.md)），本文给出的是没有参考集时的初始值。

## 1. 三层结构

| 层 | 性质 | 判定者 | 不通过时 |
|---|---|---|---|
| **H 硬约束** | 必须通过 | 代码校验 | 禁止进入下一阶段 |
| **M 工艺指标** | 有阈值，阈值取自参考分布 | 代码测量，生成评分卡 | 记为 P1，进入修复 |
| **J 评判项** | 语义与审美 | VLM 批评者按清单作答 + 两两比较 | 按 P0/P1/P2 分级进入修复 |

硬约束挡住"差"，两两比较选出"好"，两者不能互相替代。工艺指标是**下限**，不是追求的目标。

## 2. H · 硬约束

| ID | 约束 | 校验方式 |
|---|---|---|
| H1 | 规格：1080×1920，30fps，H.264 + AAC，时长与音频一致（误差 ≤ 1 帧） | ffprobe |
| H2 | 确定性：禁止 `Math.random`（未加种子）、`Date.now`、`new Date()`、运行时网络请求；同一帧渲染两次结果逐像素一致 | ESLint 规则 + 抽帧双渲染比对 |
| H3 | 设计变量：颜色、字体、字号、时长、缓动**只能引用 `theme` 中的设计变量**，不许直接写死数值 | ESLint 规则 |
| H4 | 安全区：文字和焦点元素不得超出安全区（上 8%，下 15%，左右 6%） | 无头浏览器读取元素包围盒 |
| H5 | 无重叠：文字框之间不重叠；文字不被其他元素遮挡超过 10% | 包围盒检测 |
| H6 | 可读性下限：正文字高 ≥ 画面高 × 2.5%；文字与背景对比度 ≥ 4.5:1 | 包围盒 + 背景采样 |
| H7 | 在屏时长：每组文字在屏时间 ≥ max(0.8s, 字数 ÷ 7 字每秒) | 时间轴分析 |
| H8 | 无僵帧：连续无运动时长 ≤ 1.5s（全片内） | 逐帧差分 |
| H9 | 声音：整体 -14 ± 1 LUFS，真峰值 ≤ -1 dBTP；无削波 | pyloudnorm |
| H10 | 音画同步：强调词的视觉高亮与该词语音起点偏差 ≤ ±150ms | 分镜声明 + 逐词时间戳 |
| H11 | 时间覆盖：镜头首尾相接，完整覆盖音频，无空隙、无重叠 | `storyboard_validate` |
| H12 | 素材真实：logo、产品图等身份类素材必须在素材库中登记且有来源；禁止生成或手绘替代品 | 素材清单校验 |
| H13 | 素材级别：引用的素材必须为 verified 及以上；draft 素材需人工确认后才能使用 | `asset-lock.json` + 素材清单 |
| H14 | 手法约束：分镜中声明的剪辑手法（`technique.edit`）必须满足其自带约束，如匹配剪辑的焦点距离、卡点的节拍偏差（见 [03 §1.1](03-asset-library.md#11-剪辑手法的特殊性)） | 测量 + 素材约束 |
| H15 | 授权：所有素材都有授权记录，且与用途匹配 | 素材清单 |

## 3. M · 工艺指标

初始阈值如下，有参考集后替换为参考分布的 P10–P90。指标落在区间外记为 P1。

| ID | 维度 | 指标 | 初始阈值 |
|---|---|---|---|
| M1 | 节奏 | 镜头时长 | 1.2–5.0s |
| M2 | 节奏 | 每分钟切镜次数 | 15–30 |
| M3 | 节奏 | 切点到最近词边界的距离 | P90 ≤ 120ms |
| M4 | 节奏 | 每个句子边界都有可见的画面变化 | 覆盖率 ≥ 90% |
| M5 | 节奏 | 开头钩子：第一个视觉信息点出现时间 | ≤ 0.5s |
| M6 | 文字 | 同屏文字组数 | ≤ 3 |
| M7 | 文字 | 每行中文字数 | ≤ 12 |
| M8 | 动效 | 入场时长 | 0.3–0.7s |
| M9 | 动效 | 逐个出现的间隔 | 40–120ms |
| M10 | 动效 | 位移 / 缩放使用线性缓动的比例 | 0% |
| M11 | 动效 | 同一时刻的运动焦点数 | ≤ 1（转场时除外） |
| M12 | 动效 | 运动强度曲线与语音能量曲线的相关系数 | ≥ 0.3 |
| M13 | 色彩 | 画面主要色与 theme 色板的 ΔE（OKLab） | < 3 |
| M14 | 色彩 | 单镜强调色数量 | ≤ 2 |
| M15 | 声音 | 音效起音点与画面击打点偏差 | ≤ 1 帧 |
| M16 | 声音 | 人声出现时配乐压低幅度 | 10–15 dB |
| M17 | 风格距离 | 全片各项指标与 reference-profile 的综合距离 | 低于"不带 profile 生成版本"的距离 |
| M18 | 素材 | 同一效果 / 转场每分钟出现次数 | ≤ 2，或该素材声明的 `max_per_minute` |

## 4. J · 评判项

### 4.1 规则

1. **不打分，答具体问题。** 根据分镜自动生成是非题，每题必须给出依据的时间点。
2. **两两比较，不打绝对分。** 比较对象是"当前版本 vs 参考视频同类镜头"，或"候选 A vs 候选 B"。
3. **批评者使用全新上下文。** 只看分镜 + 截图拼板，不看创作过程。
4. **修改意见格式固定：** `t=4.2s · 位置 · 问题 → 改法 · 保留什么`，分级 P0 / P1 / P2。
5. **修复最多 3 轮**，仍有 P0 则转交人工。

### 4.2 每镜清单（v0）

由分镜中的意图声明自动生成具体题目：

| ID | 问题模板 | 不通过分级 |
|---|---|---|
| J1 | 镜头焦点是否是声明的 `focal` 元素？ | P0 |
| J2 | 声明的 `metaphor` 是否在画面中可识别？（如"增长"时柱子是否在上升） | P0 |
| J3 | `emphasis_words` 是否都有视觉强调？ | P1 |
| J4 | 画面中是否有与文案无关的装饰元素在抢焦点？ | P1 |
| J5 | 信息层级是否清楚：第一眼、第二眼分别看到什么，是否符合声明？ | P1 |
| J6 | 与前后镜头的衔接是否连贯（色彩、运动方向、焦点位置）？ | P2 |
| J7 | 与参考视频的同类镜头相比，哪个更好？差在哪里？ | P2（仅记录） |

### 4.3 全片清单

- 前 3 秒是否有明确的钩子？
- 全片视觉语言是否统一，有没有"一镜一个样"？
- 节奏是否有起伏，还是始终同一强度？
- 结尾是否有收束？

## 5. 让 agent 达到规范

衡量只是一半，另一半是让 agent 一开始就离好结果更近。

1. **缩小生成空间。** 素材库（见 [03](03-asset-library.md)）中的积木、效果、转场由人精调过，来源包括参考分析的代码复刻和项目沉淀。agent 主要负责按手法选组件、组合和调参数，而不是每次从零写。
2. **先声明意图，再写代码。** 分镜中每个镜头必须声明 `intent` 字段，渲染后检查实际画面是否符合声明，评判因此有了标准答案。完整格式见 [00 §5](00-architecture.md#5-分镜格式storyboardjson)：

   ```jsonc
   {
     "id": "s03",
     "start": 6.40, "end": 9.15,
     "text": "用户留存率提升了 37%",
     "block": "block/stat-punch@1.2",
     "intent": {
       "focal": "数字 37%",
       "metaphor": "growth-rise",
       "emphasis_words": ["37%"],
       "motion": "数字计数到 37 后弹一下，说明文字随后入场"
     },
     "beats": [{ "t": 7.10, "word": "37%", "event": "count-end", "sfx": "sfx/hit-short@1.0" }]
   }
   ```
3. **关键镜头多做候选。** 钩子、核心论点这类镜头生成 2–3 个方案，用两两比较选优。
4. **把品味沉淀成规则和素材。** 每一次人工纠正都落成以下之一：一条 lint 规则、一个阈值调整、一个素材改进、一条回归用例；做得好的镜头经 `asset_promote` 回流素材库。规范和素材库都是长出来的，不是一次写完的。

## 6. 规范本身的验证

指标不一定和"好看"相关，需要用人的偏好来校准：

- 记录每次人工 A/B 选择（`evals/preferences.jsonl`）。
- 定期检查各项 M 指标对偏好的预测力；预测不了的指标删除或降为仅供参考。
- 维护一组固定的标准需求（`evals/briefs/`），每次修改积木、规则或 prompt 后重跑，比较硬约束通过率、各级问题数、耗时和成本。

## 7. 评分卡

每次渲染后由 `scorecard` 生成，供 agent 和人阅读：

```jsonc
{
  "project": "retention-explainer",
  "round": 2,
  "hard": { "pass": false, "failed": [ { "id": "H5", "t": 4.2, "detail": "标题与图例重叠 18%" } ] },
  "metrics": [
    { "id": "M1", "value": { "p50": 2.9 }, "band": [1.2, 5.0], "ok": true },
    { "id": "M12", "value": 0.18, "band": [0.3, 1.0], "ok": false }
  ],
  "judgement": [
    { "shot": "s03", "id": "J2", "severity": "P0",
      "assets": ["block/stat-punch@1.2.0"],
      "note": "t=7.0s · 中部 · 柱子是静止的，没有体现增长 → 让柱子从 0 生长到目标值 · 保留配色和数字位置" }
  ],
  "profile_distance": { "with_profile": 0.21, "baseline": 0.47 }
}
```

## 8. 相关 MCP 工具

| 工具 | 作用 |
|---|---|
| `storyboard_validate` | H11、H10 的声明部分、H13、H15、意图字段完整性 |
| `scene_check` | H2、H3（TypeScript 类型检查 + ESLint） |
| `scene_inspect` | H4–H8，基于无头浏览器读取包围盒和逐帧差分 |
| `scene_measure` | M 系列指标与 H14 手法约束，与 `video_analyze` 共用测量库 |
| `scene_snapshot` | 生成节奏点和切点前后 ±0.2s 的拼图，以 image content 返回 |
| `review_record` | 写入 J 系列意见，统计修复轮数 |
| `scorecard` | 汇总生成评分卡；按问题归因更新素材的 `uses` / `p0_rate` |
