# 参考集 chaping · 第一阶段分析报告

- **参考集**：5 条视频（`video/`）。4 条为差评君竖屏 shorts（9:16，150–180s），1 条为 vibe-motion `hoverslam` 横屏讲解（16:9，172s）。两种画幅分开统计，不混合。
- **产物**：`reference-profile.json`（分布）、`labels/`（L5 标注）。逐视频的原始测量、转写和拼图在 `videos/` 下，不进 git。
- **工具**：`measure/`（测量内核）+ `server/`（MCP：`video_analyze` → `analysis_sheet` → `segments_label` → `profile_build`）。

## 1. 测量层验证（E1）

| 项目 | 方法 | 结果 | 结论 |
|---|---|---|---|
| 响度 | pyloudnorm 与 ffmpeg ebur128 交叉验证 | 5 条视频偏差均 ≤ 0.07 LU | ✅ 可信。早期版本在单声道下混上测量，偏低约 3 LU，已修正 |
| 字幕文字 | 字幕 OCR 与语音识别逐字比对（两种独立工具互证） | 一致率 0.83–0.95 | ✅ 两边都可信；横屏为 0.83，字幕为斜体花字 |
| 硬切检测 | 人工复核 2 条视频的检出切点与接近阈值的被拒候选 | F1 ≈ 0.86 / 0.84 | ✅ 阈值用第 1 条视频定，在第 2 条上验证，没有过拟合。漏检主要是叠化 / 遮罩转场 |
| 视觉节拍 | 人工复核 1 条视频中的一段 33s 黑底 MG 讲解 | 检出点与目测的画面切换基本一一对应；全片节拍准确率约 0.85 | ⚠️ 召回率尚未系统评估 |
| 版式检测 | 目测 | 4 条竖屏都正确找出内容区（约 y 17%–62%，占画面 40%） | ✅ |
| 入场时长 | 模板跟踪 | 能给出时长和滑入方向 | ⚠️ 未与人工标注比对 |
| 入场缓动曲线 | 对位移曲线拟合 cubic-bezier | 聚类结果分散，不稳定 | ❌ 不可用，暂不作为规范依据 |
| L5 标注 | 客户端模型（Claude）单人标注 | 竖屏 1 条 65 段全标；横屏 59 段标了 28 段 | ⚠️ 单人、单遍，无一致性检验 |

**方法上的两点修正，都是做的过程中才发现的：**

1. **MG 视频的节奏单位不是切点，是"视觉节拍"。** 差评君有大段内容是在同一个黑底上连续换图形（一段 33s 的"镜头"里有 9 个画面）。颜色直方图看不出这种变化，所以加了基于空间结构的节拍检测。**段 = 硬切 ∪ 节拍**，段是 L5 标注单位。
2. **对齐类指标必须和随机基线比。** 中文逐字时间戳很密，随便一个时刻离最近的字边界也只有约 50ms。只看"切点离字边界 60ms"会得出"切点卡字"的错误结论。

## 2. 竖屏：差评君（4 条）

### 2.1 版式（L2）

- **固定的"复古窗口"模板**，4 条视频完全一致：
  - 黑底网格背景；
  - 中部窗口为内容区（x 6%–94%，y 17%–62%，占画面 40%）；
  - 窗口内底部是白色字幕条（中心 y ≈ 0.656）；
  - 画面底部是常驻的绿色话题标题栏和栏目 logo。
- **字幕**：字高约为画面高度的 2.8%（1920 高约 54px）；每行中位 8 字，P90 为 13 字；每条停留中位 1.5s。
- **色彩**：近黑 `#0F1011`（42%）+ 白（19%）+ 低饱和灰绿，整体彩度极低（C 中位 0.012）。品牌绿只出现在标题栏和少数 MG 图形上。

### 2.2 节奏（L1）

| 指标 | P10 | P50 | P90 |
|---|---|---|---|
| 硬切 / 分钟 | 7.3 | 8.2 | 12.2 |
| 视觉边界（硬切 + 节拍）/ 分钟 | 19.4 | 21.5 | 23.5 |
| **段时长 (s)** | **1.0** | **2.4** | **4.4** |
| 每个硬切镜头内的段数 | 1 | 1 | 5 |
| 语速（字 / 分钟） | 332 | 340 | 351 |
| 停顿（≥0.15s）/ 分钟 | 1.2 | 1.7 | 3.0 |

- **语速快且几乎不停顿**，每分钟约 340 字，开头没有空白，第一个字就在 0s。
- **画面每约 2.4s 变一次。** 硬切只占视觉变化的约 40%，其余是同一镜头内的 MG 场景切换。
- **画面变化只是松散地跟着短语走**：到短语边界的距离比随机时刻近 1.34 倍。不卡字，也**不卡音乐节拍**：到节拍的距离中位数 101ms，随机水平是 123ms。
- **开头**：前 4–9s 是标题大字加栏目 logo 片头，第一个硬切在约 7.8s。

### 2.3 动效（L3）

- 文字入场时长中位 0.43s（P90 1.2s），29% 是直接出现、没有过渡动画。
- 80% 的入场带滑入，位移约为画面短边的 19%。方向以从下进入最多（35%），其次从上（25%）。
- 运动强度与语音能量几乎不相关（r ≈ 0.07）。

### 2.4 修辞（L5，1 条视频 65 段）

| 维度 | 分布 |
|---|---|
| 画面类型 | 素材实拍 46% · 黑底 MG 图解 40% · 大字 6% · 其他 8% |
| 隐喻 | 无（直接图示）80% · 对比分屏 9% · 流动路径 6% · 其他 5% |
| 强调方式 | 无 71% · 放大 18% · 方框 6% · 弹出 3% |
| 进入方式 | 镜头内转场 65% · 硬切 35% |

**解读：** 差评君的"高级感"主要不来自复杂的视觉隐喻，而来自三点：

1. 统一模板带来的强识别度；
2. 快节奏的"一句话一画面"直译，用素材或简洁图解把每个名词画出来；
3. 原理部分用黑底极简 MG 图解，讲完原理马上回到生活化的实拍素材。

## 3. 横屏：vibe-motion hoverslam（1 条）

- **画面构成**：3D 物理模拟 + HUD 数据面板 + 公式逐项推导 + 论文截图高亮 + 实拍蒙太奇。和你要做的"3D 场景 + 数据可视化"方向最接近。
- **节奏**：段时长中位 2.2s；火箭着陆蒙太奇是连续 5 个 0.43s 的快切。**41% 的硬切落在语音停顿里**（竖屏几乎为 0）。语速约 275 字 / 分钟，较慢。
- **文字**：字幕在底部（中心 y ≈ 0.89），字高约 5%；画面文字中位 4.6%，比竖屏的 1.9% 大一倍多。
- **入场**：43% 直接出现，节奏更硬朗；滑入从右进入最多。
- **修辞**（28 段）：3D 场景 / 物体 32%、实拍 39%、截图 7%、图表 / 时间轴各 4%。隐喻使用比差评君多：放大细节、形变、遮罩揭示、累积叠加。
- **可借鉴的具体手法**，都可以作为素材库的配方候选：
  - 半透明轨迹叠加表达"模拟了几百次"；
  - X 光透视揭示内部结构；
  - 公式逐项追加，新加的项变色；
  - 年份滚动配刻度尺；
  - 在论文配图上用描线揭示答案；
  - 每句关键词变色、逐字打出的金句页。

## 4. 对质量规范 v0 的修订建议（竖屏）

把 [docs/02](../../docs/02-quality-spec.md) 中没有参考依据的初始值，和参考分布对比：

| 规范 | 初始值 | 参考分布 | 建议 |
|---|---|---|---|
| M1 镜头时长 | 1.2–5.0s | 段时长 1.0–4.4s | **改为"段时长"** 1.0–4.4s，中位约 2.4s |
| M2 切镜次数 | 15–30 / 分钟 | 硬切 7–12，视觉边界 19–24 | 拆成两条：视觉边界 19–24 / 分钟；硬切不设下限 |
| M3 切点到词边界 | P90 ≤ 120ms | 与随机无差异 | **删除**，改为"到短语边界的对齐倍数 ≥ 1.3" |
| M8 入场时长 | 0.3–0.7s | P10 0（直接出现）· P50 0.43 · P90 1.2 | 改为中位 0.3–0.6s，允许约 30% 直接出现 |
| M12 运动与语音能量相关 | ≥ 0.3 | ≈ 0.07 | **删除**，参考视频不满足，说明这条与质量无关 |
| M6 同屏文字组数 | ≤ 3 | P90 约 4（含常驻标题栏） | 不计常驻模板后保持 ≤ 3 |
| H8 最长无运动 | ≤ 1.5s | 中位 3.6s，P90 8.8s | 放宽到 ≤ 4s，并只计内容区 |
| H6 正文字高 | ≥ 2.5% | 字幕 2.8% | 保持 |
| H9 响度 | -14 ± 1 LUFS，峰值 ≤ -1 dBTP | -14.4 LUFS，峰值 -0.6 | 保持（我们的标准比参考更严） |

这些修改等你确认后再写进 docs/02。

## 5. 局限与下一步

1. **样本小**：竖屏只有 1 位作者 4 条，横屏只有 1 条。横屏的分布不能当作规范，只能作为手法来源。
2. **还没测到的**：配乐压低幅度、音效与画面击打点的对齐、非文字元素（图标、3D 物体）的入场、缩放 / 旋转类动效曲线。
3. **L5 只标了 1.5 条视频**，而且是单人标注。建议你抽查 `labels/` 里的几段，校准词表的用法。
4. **下一步（按 docs/00 §8）**：
   - 搭引擎最小版：theme 按本报告的竖屏版式和色板定，先做 3 个积木（黑底 MG 图解、大字标题、素材窗口）；
   - 把横屏视频里 3 个手法复刻成积木：轨迹叠加、HUD 数据面板、公式逐项追加；
   - 用重建测试（E2）检验这份 profile 是否真的抓住了风格。
