# 评测结果

## 2026-11-09 · v0.2 重构后首次合成集评测（调参集 seed=1）

- **数据**：`vh eval synth --n 4 --seed 1 --scale 0.5`，4 条视频（共 26 个镜头，约 2 分钟），960×540。真值来自场景图。
- **算法**：`analyze/` 的版式感知 + 两段式硬切 + 视觉节拍，阈值沿用旧 `measure/`（当初在竖屏 MG 参考集上人工复核定下），本次未调参。
- **独立性**：阈值不是在本数据上定的，但这是第一次在合成集上跑，之后改算法时 seed=1 即为调参集；留出集（seed≥2）尚未运行。

| 指标 | 结果 | 说明 |
|---|---|---|
| 硬切召回 | **0.882**（15/17） | 容差 2 帧 |
| 硬切精确率 | **0.944** | 检测到的切点落在真实硬切或转场区间内即算对 |
| 转场召回（fade / push / wipe / zoom） | 0.667（2/3） | 样本太少，只作参考 |
| 文字出现事件召回（视觉节拍代理） | **0.156** | 节拍检测只对"构图的实质变化"敏感，单个标签 / 数字入场基本测不到 |

**已知失败**：

1. 漏掉的 2 个硬切都在**同一章节色板的相邻镜头**之间（v01：棕褐色板下 stat-crowd → title-card → process-diagram）。确认步骤用颜色直方图距离，底色相同时距离不够；其中一个被视觉节拍在 0.28s 前捕获。→ 改进方向：确认步骤加入空间结构差（与节拍检测同一特征）。
2. 文字出现事件召回低：小元素入场不会触发 32×32 结构差。对参考视频来说这意味着"镜头内的元素级动效"仍然测不到——这正是路线图里"元素轨迹"那一项要解决的；对自己的成片，元素信息直接来自场景图，不依赖这项检测。

**示例项目自检**（`examples/sky-blue`，真实 ElevenLabs 配音，`vh_analyze run --asr file:voice.json`）：5 个镜头边界（含 3 个 fade / zoom 转场）全部检出、无误报；画面变化落在停顿里的比例 0.625（随机 0.182），短语对齐倍数 7.8。

## 历史（旧架构，仅供对照）

旧 `measure/` 在竖屏参考集上的人工复核：硬切 F1 ≈ 0.86 / 0.84（两条视频，阈值在第 1 条定、第 2 条验证）；视觉节拍准确率约 0.85（召回未系统评估）；入场缓动拟合不稳定，已退役。
