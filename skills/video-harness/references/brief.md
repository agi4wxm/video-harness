# 创意简报（brief.md）

简报在分镜之前，决定这条片子"像什么"。格式沿用高质量提示词的六段结构，`vh check brief` 会检查每段非空、有禁用清单、并且用户已确认（front matter `status: approved`）。

| 段落 | 写什么 | 反例 |
|---|---|---|
| `inputs` | 题目、观众、时长、语言、必须出现的事实和出处、用户要提供的素材。**只问会改变成片的问题**，其余用默认值并写明 | 问一堆无关紧要的偏好 |
| `direction` | 审美方向：设计包与章节色板、语义色（实体 → 颜色，全片固定）、母题（反复出现的物体 / 角色）、参考了哪些原则（[taste/](taste/)）；**一行 `Banned: …`**（按题材的禁用清单，见 [anti-cheap.md](anti-cheap.md)） | "现代、简洁、高级" |
| `structure` | 钩子（前 3 秒的矛盾 / 问题）→ 问题 → 解释 → 证据 → 收束；每段大约几秒、在哪换章节色、在哪留停顿 | 平铺直叙的要点列表 |
| `build` | 每段用哪个积木、哪些要专门写本地镜头（local / html / react）；明确"不用生成式视频" | "用合适的动画" |
| `gotchas` | 这条片子的坑：文字在屏时间、数字怎么排、哪个画面容易做成界面感 | — |
| `start` | 第一步做什么，通常是"先给我看节拍表（每拍的视觉想法），确认后写代码" | — |

## 好简报的特征

- 每个抽象概念都对应一个**具体的画面想法**（生存率 → 一群小人有多少变绿；药物流动 → 身体变成发光的网格）。
- 有贯穿全片的母题和固定语义色，观众不读字也知道谁是谁。
- 结构里写清楚节奏：话说完一句、换口气，画面才换（讲解类横屏的典型做法，见 [taste/explainer-illustrated.md](taste/explainer-illustrated.md)）。

完成后把简报发给用户确认；用户同意后把 front matter 改成 `status: approved`。
